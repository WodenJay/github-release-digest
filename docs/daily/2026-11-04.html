tw93/Pake ↗ 1 release · 1 stable
V3.18.0V3.18.0 Haven Stable2026-11-04T14:42:57Z

<div align="center"> <img src="https://raw.githubusercontent.com/tw93/Pake/main/assets/logo.png" alt="Pake Logo" width="120" height="120" style="border-radius:50%" /> <h1 style="margin: 12px 0 6px;">Pake V3.18.0</h1> <p><em>Turn any webpage into a desktop app with one command.</em></p> </div>

Changelog

  1. Downloads on Windows now show the native WebView2 download panel with progress, and same-site downloads go through it too.
  2. Dragging files onto a page to upload them now always works. --enable-drag-drop used to block those drops, and on Windows it also broke drag and drop inside pages; it is now accepted but ignored, so existing build commands keep working.
  3. Downloaded files keep their real names, so a link to Annual Report.pdf or 报告.pdf is no longer saved as Annual%20Report.pdf or %E6%8A%A5%E5%91%8A.pdf.
  4. The tray menu follows the system language, with Simplified and Traditional Chinese labels.
  5. After a failed build on Windows, the next build starts normally instead of stopping on a leftover compilation cache lock.
  6. Apps built without --icon get the new flat mother-and-baby icon, the same one Pake for Mac and Windows uses.
  7. Dependencies are updated for published RustSec and npm security advisories.
  8. The docs now live at pake.run, with a step-by-step getting started tutorial and pages for shortcuts, scripts and AI agents.

更新日志

  1. Windows 上下载文件会显示 WebView2 自带的下载面板和进度，同一网站内的下载也走这个面板。
  2. 把文件拖到网页上上传现在都能正常用了，以前加了 --enable-drag-drop 反而会拦下这些文件，Windows 上网页里的拖拽也会失效，这个参数现在保留但不再生效，已有的打包命令照常能用。
  3. 下载的文件保留原来的名字，Annual Report.pdf 或 报告.pdf 这样的链接不会再存成 Annual%20Report.pdf、%E6%8A%A5%E5%91%8A.pdf。
  4. 托盘菜单跟随系统语言，中文系统上显示简体或繁体中文。
  5. Windows 上构建失败后，下一次构建能正常开始，不会再被残留的编译缓存锁挡住。
  6. 没有指定 --icon 时，应用默认用新的扁平母婴图标，和 Pake 桌面版用的是同一个。
  7. 依赖已按公开的 RustSec 和 npm 安全公告更新。
  8. 文档搬到了 pake.run，新增一步步的入门教程，以及快捷键、脚本和 AI Agent 相关的页面。

Special thanks to @WavesMan, @NgoQuocViet2001, and @jakero for the pull requests behind this release. If Pake helps you, please consider giving it a star and recommending it to your friends.

Known issue found after release: GT_ROOT in .beads/.env is ignored

1.3.3 imports only an allowlist of keys from a project's .beads/.env (#7879). Gas City's gc rig add writes GT_ROOT=<city root> into each rig's .beads/.env, and 1.3.3 drops it. Every bd command in a rig prints beads: ignoring GT_ROOT from .beads/.env on stderr.

But released gc versions read bd's JSON error from stdout only when stderr is empty, and the notice fills stderr. A bd failure in a rig (for example a missing id) can therefore surface as the notice text instead of bd's error. gc's fix is gastownhall/gascity#8817.
  • When you run bd by hand in a rig without GT_ROOT exported, the city's formulas ($GT_ROOT/.beads/formulas) and town molecules are not found. The repo's own .beads/formulas and ~/.beads/formulas still work. Workaround: export GT_ROOT=<path to your city> before running bd in a rig.

Nothing else is affected: no data, Dolt server selection or credentials. Fixed in bd 1.3.4, which allows GT_ROOT from .beads/.env again (#8117/#8118) and removes the notice for every gc version. Upgrade to 1.3.4.

🌟 Codename: CoRouter for Teams

Unlimited seats. Shared credits. One subscription gives your team shared access to model credits. Invite colleagues to your workspace for free, with no extra seat fees. Create in Open Design or call models through the API using the same shared credits. The workspace owner manages the subscription, upgrades and top-ups.

🔥 Highlights

  • 🤝 Invite colleagues, share the workspace. Send email invitations from onboarding or Home, let teammates join your workspace, and collaborate on shared projects. Invitations show which emails succeeded and which need another attempt, so you can retry failed entries without sending successful invitations again. (#9120)
  • 💳 One workspace, shared credits. See the workspace's shared Design Plan and metered allowance, with plan and model availability refreshed when the subscription changes. When balance or concurrency prevents a task from starting, your draft stays available; resolving the limit leaves you in control of when to send again. (#9120, #9138)
  • 🔐 Choose what the team can see. Set a project's visibility to yourself or team members, including in the default Personal workspace. Keep workspace visibility separate from publishing a work link for review. (#9120, #9193)
  • 🎞️ Start your motion piece from a reference video. Attach a video or paste a supported video link and ask for a recreation. The Agent can inspect its timing, scenes and soundtrack, build editable motion, and export an MP4. Ask to change a specific element for a focused revision; results still need your review. (#9105)
  • 🎨 Thirteen more ways to get moving. New Motion templates cover product launches, ticket promotions, explainers, kinetic typography and more. Titles, descriptions, starter prompts and input labels follow all 19 supported client languages, with improved preview font loading and sizing. (#9131)
  • 🧠 Planning and making read as one task. Automatic planning and production share one expandable process and a running total of elapsed time. Steps stay in order, while the final answer and deliverables remain easy to find outside the process. (#8735, #9196)
  • 💬 Keep the feedback you already have. A failed comment refresh keeps existing comments visible with a retry action. Read status follows the comments actually shown, and saved location markers stay aligned with the selected comment. (#9027) Thanks @alchemistklk.
  • 🗂️ Recent projects follow your work. Home and the project list sort by your latest accepted message or manual retry. Opening a project, renaming it or receiving an Agent reply no longer pushes it ahead of work you just started. (#8802) Thanks @alchemistklk.

📥 Download: Find desktop installers on GitHub Releases.

More reliable terminals, dependable chats & easier AI choices ✨

  • 🖥️ More reliable terminals: Keep active remote streams connected, preserve agent identity across daemon restarts, improve ordered mobile input and long messages to Windows Codex, and render Nerd Font symbols correctly after fonts load.
  • 💬 More dependable conversations: Keep streaming replies after their prompts, hold queued follow-ups when a turn fails, and keep pasted text and terminal drafts separate from chat sends.
  • 🎛️ Choose how AI writes for you: Pick Model and Effort for commit messages, pull-request descriptions, branch names and chat names from the Source Control settings.
  • ⚡ Less unnecessary chat work: Preview updates avoid copying the full loaded conversation, and this release removes the live-history cleanup that could stall large chats.
  • 📱 Better phone continuity: Reopen chats from cached messages, keep options current, and send long messages to Windows Codex more reliably.
  • ⏳ Choose when updates arrive: Add an optional update delay in Settings, with a one-time option to skip the wait.
  • 📝 Editor & workspace improvements: Opt into format on save, search theme pickers, and use familiar right-click actions on chat tabs.

Highlights

  • Terminals: Remote streams stay connected while output is flowing, agent identity survives daemon restarts, mobile input is pipelined in order, and long phone messages reach Windows Codex. Nerd Font symbols repaint once fonts load, and closed terminal workers can reopen from their orchestration cards.
  • Chat continuity: Streaming replies stay after the prompt they answer. Follow-ups remain queued after a failed turn, expired attachments are identified when a send is refused, and pasted text can be opened from structured chats.
  • Agent startup & choices: A final startup refusal is shown after the first attempt instead of repeated retries; temporary failures still recover. Chats preserve configured effort when you have not chosen an override, and Source Control text actions use Model and Effort menus.
  • Phone: Cached chats reopen before fetching changes. Chat options, terminal settings, branch and pull-request details refresh more reliably; long phone messages reach Windows Codex, and browser tabs hosted by a desktop server can stream to the phone.
  • Updates & Windows: Choose an update delay, retain a moved Windows installation's location during updates, and get a clearer explanation when installation is incomplete.
  • Editor & navigation: Enable format on save, search theme choices, highlight selected Markdown table cells, and use image zoom shortcuts outside editor tabs.
  • Orchestration & plugins: The Orchestration panel is available again as an experimental opt-in. Closed terminal workers can reopen from their cards, native chats receive complete orchestration messages, and enabled status bar plugins keep their workers running.
  • Performance & reliability: Chat preview updates avoid a redundant full-history copy, cached text scrolling avoids whole-file layout updates, and diagnostic logging uses less data. The preview change removes unnecessary work; no whole-app latency improvement is claimed.

Compatibility & upgrade notes

  • Update delay is optional: Settings → General → Updates offers None, 1, 3, 7, 14 or 30 days. None remains the default, and Skip Delay Once bypasses a held update.
  • Format on save is optional: Existing editing behavior stays the same until you enable it.
  • Orchestration panel: This release restores the experimental opt-in after the earlier panel disablement.
  • Phone changes: Phone app changes require an updated Orca Mobile app as well as a compatible desktop or server.
  • Saved chat history: The live-history cleanup added earlier has been rolled back. Existing saved conversations, including already-compacted histories, remain readable.

Known issues

Saved chat storage: Live-history compaction is paused, so chat storage can grow as conversations continue. This release does not claim to remove every source of chat stalls.

Long update delays: With a 14- or 30-day delay, a release can leave the update feed before it becomes eligible. None and Skip Delay Once remain available.

GitHub issues on older paired servers: Opening an issue through a repository or URL can leave title, label and assignee editing unavailable. Local and project-origin routes are unaffected; Open on GitHub remains available.

Plugin command replacements: A plugin replacing a built-in command can still finish after Orca has used the normal command instead, causing the action to happen twice.

A large correctness, performance and workflow release spanning the extractors, the query layer, incremental update, the hooks, the skill runbook and install.

Call-resolution (extractors)

  • go: same-file member calls resolve through the receiver's type; cross-package pkg.T receivers bind only via the file's import; interface method calls dispatch to implicit implementers (#4966, #4853, #4934).
  • rust: module-qualified calls (crate::b::helper()) resolve cross-file; calls inside expression-macro arguments are linked (#4944, #4945).
  • kotlin: overloaded and init {}-block calls resolve; unreachable external-inherited calls are dropped (#4956).
  • python: a module-level singleton's member calls resolve through its type; a bare method call no longer self-binds (#4972, #4933).
  • js/ts: class extends through a CommonJS require resolves; a typed tagged template and an import("mod").T<X> annotation no longer half-parse or mint a false dynamic_import edge; default-exported object methods resolve (#4700, #4976, #4967).
  • solidity: ../ imports resolve to the real file (#4985).
  • cpp: receiver typing from params/fields, split-header owner binding, local-callable suppression, type-alias exact-spelling (#4946, #4920, #4921, #4951).

Query

  • Source nodes rank above tests and docs (a soft weight, not exclusion), and answers are file-first (#4982).
  • graphify query reads query_budget/query_depth from .graphifyrc and gains a --depth flag (#4760).

Incremental update / watch

  • graphify update re-extracts only the files whose content changed, with a graph identical to a full rebuild; a contended incremental request is recorded instead of dropped (#4800, #4801, #4802).

Build / cache

  • The write guard no longer counts intentional ghost folds or dedup folds as dropped nodes; independently-sourced semantic evidence survives a fold; cache keys are case-preserving (#4957, #4952, #4927, #4950, #4937).

Hooks

  • A file unchanged in content is not re-flagged stale by mtime; a dedicated Grep is held to the strict orientation gate; external searches emit no project hint (#4974, #4973, #4979).

Performance

  • Lower peak memory in load, resolution and extraction, and a faster cross-file repoint — all with identical output (#4960, #4958, #4959, #4981).

Skill / install

  • The --update runbook re-queues partly-read docs instead of stamping them done; Step 4 threads --force; a hub-bypass report is added; uninstall removes the global skill registration (#4816, #4805, #4704, #4975).

The AST cache schema is bumped to 37; warm caches re-run the affected extractions.

v7.0.2 Stable2026-11-03T22:17:54Z

This release further tunes brainstorming's questions. It asks fewer of them, starts by asking why, and when there's a choice to make it gives you options to pick from. It also fixes bootstrap problems on six harnesses, and makes the SDD and executing-plans helper scripts much harder to point at the wrong repository or the wrong task.

Brainstorming

  • It asks a question only when the answer would change what gets built and nothing already answers it. Otherwise it states its call as a proposal you can correct. It also stops asking about process: writing things up, where files go, whether to look further, and how to show you something are its own calls, and it tells you what it decided. (#2644)
  • When you haven't said why you want something, that's the first thing it asks. It asks openly, with no example answers to pick from. (#2644)
  • When there's a choice it can name, it shows you the options with a recommendation. In one of our test scenarios, where a spec gives Ctrl+K to two features, 7.0.1 found the conflict every time but asked a bare "which one?" in 8 of 8 runs. This release laid out the options and recommended one in 8 of 8. (#2644)
  • It reads from how you talk whether you want to discuss the technical choices, and when your request leaves nothing open, its first message is a short design for you to approve. (#2644)
  • In blind-graded test conversations, filler questions dropped from 41 with 7.0.1 to 23, the reason behind the request came out before any approach in 33 of 33 conversations (28 of 33 before), and nothing got built before approval (4 times before). Against 6.4.2's brainstorming in the same scenarios, it had fewer filler questions (23 against 34), drew out the why far more often (33 of 33 against 19 of 33), and matched it at building nothing before approval. (#2644)
  • start-server.sh --project-dir . now works. The script cds into its own directory before starting the server, so every path it derived from a relative --project-dir pointed to the wrong place, and the server never started. It now resolves the directory first. Thanks @anchore-jesset for the report. (#2524, #2608)

Thanks to @mbcrawfo and everyone on #2530 who sent transcripts and tested 7.0.1. If brainstorming still asks you something it shouldn't, please tell us there, with what you asked and what it asked back.

Hooks

  • Copilot on Windows now gets the bootstrap. Copilot CLI and VS Code Copilot run hook commands through PowerShell, which rejected the SessionStart command with a ParserError. hooks.json now has a powershell form of the command. Thanks @ronpieper-engcp and @orty for the reports. (#2189, #1225, #2592)
  • The SessionStart hook starts no child processes. On Git Bash, each one costs tens of milliseconds, and the hook started six of them on every startup, /clear and compaction. Thanks @midirectiekade14-debug for the report and measurements. (#2081, #2593)
  • On a Unix system without bash, run-hook.cmd falls back to zsh, or exits quietly. It used to exit 127 with bash: not found, and the bootstrap was lost. (#2503, #2594)

Pi

  • Every prompt now gets the bootstrap. The extension turned the bootstrap off after the first prompt of a session, so every later prompt went without it. Because the first message of the request changed, Anthropic prompt caching also rewrote the whole conversation's cache on the second prompt. Over a day of sessions, @sjawhar measured 83% of first-to-second-prompt transitions rewriting the cache. Thanks @DKnight927 for the report. (#2083, #2595)
  • The skills filter on the Superpowers package entry works. The extension re-added the whole skills/ directory after pi applied the filter, so "skills": [] still loaded all 15 skills. Thanks @adrian-85 for the report and @m2dumpling for the fix. (#2394, #2402, #2598)

Hermes Agent

  • delegate_task subagents no longer get the controller's bootstrap. Every child started with an empty history, so each one looked like a new session and got the full bootstrap, and some started by loading using-superpowers instead of doing their task. Thanks @thealps01-netizen for the report. (#2536, #2596)

OpenCode

  • The bootstrap tells the model to use bare skill ids. OpenCode registers skills as brainstorming, not superpowers:brainstorming, so a model that copied the namespaced form from the bootstrap got "skill not found" and went on without the skill. Thanks @shiluoluo16 for the report. (#2583, #2597)
  • A prompt that mentions EXTREMELY_IMPORTANT no longer turns the bootstrap off. The plugin decided the bootstrap was already there if the first message contained that word, so asking "is there an EXTREMELY_IMPORTANT block in your context?" was enough to drop it. It now looks for the bootstrap's own first line. Thanks @Swift22 for the report. (#2197, #2600)
  • OpenCode 2's compaction and generate requests carry the bootstrap. Without it, the compaction request, the largest of the session, missed the prompt cache. Thanks @tpischke for the report and measurements. (#2391, #2601)

Muse

  • The SessionStart hook now runs on Debian and Ubuntu. Muse's manifest ran hooks/session-start, a bash script, with sh. Where sh is dash, the hook failed with exit 2 and the bootstrap never loaded. It now runs with bash. Thanks @rahul05ranjan for the report and @twotnguyen for the fix. (#2528, #2533)

Subagent-Driven Development and Executing Plans

  • The helpers act on the repository of the current directory, as git does, and take -C DIR to point at another. Outside a repository, sdd-workspace used to write its workspace into whatever directory the agent was in, often the plugin cache. All five helpers now stop with exit 2 and a message that tells your agent what to do. In a new project with no commits yet, your agent will need to run git init and make a first commit before it can start. -C also lets a controller review a worktree without a cd … ; prefix that Claude Code can't allowlist. Thanks @abat-kek, @rz1989s, and @jiyimeta for the reports. (#2429, #2242, #1799, #2606)
  • The skills say to run the helpers by absolute path from your working tree. They used to say "from this skill's directory", and agents that cd'd there ran the helpers against the plugin's own files. A test now fails if a skill names a helper by a relative path. Thanks @anchore-jesset for the report. (#2525, #2607)
  • task-brief finds tasks with IDs like A1, 6b, and 2.1. It used to reject letter-first IDs entirely, and asking for Task 6 also picked up Task 6b. When a plan's task headings aren't in English, it now says they must use the word "Task" and shows the headings it found.   • task-brief refuses a brief that an unclosed code fence ran to the end of the plan. One missing closing fence hid every later task heading, and the reporter's 177-line task came back as a 1,159-line brief holding five tasks. Thanks @bobbykim89 for the report. (#2436, #2605)

v0.31.4 — Stricter dataset export, COCO-exact recall buckets, and a closer NumPy fallback

Fourteen bug fixes: stricter dataset export, COCO-exact recall buckets, sturdier VLM parsing, and a NumPy fallback closer to OpenCV.

  • CreateML and Pascal VOC export raise a clear ValueError for a class_id outside classes.
  • DetectionDataset.merge keeps annotations that have no class IDs instead of raising.
  • MeanAverageRecall counts boundary-area objects in both COCO size buckets, like MeanAveragePrecision.
  • Qwen and PaliGemma parsing keep valid boxes and class labels beside malformed ones.
  • Without OpenCV, image reads, gray conversion, drawing colors and keyword parameters match OpenCV.

Drop-in upgrade; see the Migration guide if you export out-of-range class IDs or compare mAR values or fallback pixels against stored references.

✨ Spotlights / highlights

Dataset export rejects out-of-range class IDs

detections_to_createml_annotations and detections_to_pascal_voc now raise ValueError for a class_id outside classes, as detections_to_labelme_shapes already does. A negative id was exported under the last class name, and an id past the end raised IndexError. (#2859)

import numpy as np
import supervision as sv
from supervision.dataset.formats.createml import detections_to_createml_annotations

detections = sv.Detections(
    xyxy=np.array([[10.0, 10.0, 50.0, 50.0]]), class_id=np.array([-1])
)
detections_to_createml_annotations(detections, classes=["cat", "dog"])
# ValueError: class_id -1 at detection index 0 is out of range for classes list of length 2.
# 0.31.3: exported with the label "dog"

DetectionDataset.merge keeps annotations without class IDs

Merging datasets used to raise ValueError when some annotations had no class_id. They are now kept as they are while labeled annotations are remapped. (#2858)

import numpy as np
import supervision as sv

labeled = sv.DetectionDataset(
    classes=["a"],
    images=["x.jpg"],
    annotations={
        "x.jpg": sv.Detections(xyxy=np.array([[0.0, 0, 5, 5]]), class_id=np.array([0]))
    },
)
unlabeled = sv.DetectionDataset(
    classes=["b"],
    images=["y.jpg"],
    annotations={"y.jpg": sv.Detections(xyxy=np.array([[0.0, 0, 5, 5]]))},
)
merged = sv.DetectionDataset.merge([labeled, unlabeled])
merged.classes
# ['a', 'b']  (0.31.3: ValueError)

MeanAverageRecall size buckets match COCO

An object whose area is exactly 32² or 96² now counts in both neighbouring size buckets, the inclusive ranges pycocotools and MeanAveragePrecision use. It used to land in only one, so mAR and mAP disagreed on the small, medium and large results. (#2848)

import numpy as np
import supervision as sv
from supervision.metrics import MeanAverageRecall

box = np.array([[0.0, 0.0, 32.0, 32.0]])  # area is exactly 32²
target = sv.Detections(xyxy=box, class_id=np.array([0]))
prediction = sv.Detections(xyxy=box, class_id=np.array([0]), confidence=np.array([0.9]))

result = MeanAverageRecall().update([prediction], [target]).compute()
result.small_objects.mAR_at_100, result.medium_objects.mAR_at_100
# (1.0, 1.0)  (0.31.3: (0.0, 1.0))

🔄 Migration guide

No public symbol was removed or renamed, and nothing is deprecated. A few fixes change what existing code returns or raises:

  • New error: CreateML and Pascal VOC export raise ValueError for a class_id outside classes. Make sure every exported id indexes into your classes list; filter or remap ids such as -1 first. (#2859)
  • Different numbers: MeanAverageRecall small, medium and large results can change for datasets with objects of area exactly 32² or 96². (#2848)
  • Different pixels without OpenCV: drawing colors saturate instead of wrapping, uint16 gray conversion and 16-bit grayscale reads follow OpenCV, and IMREAD_GRAYSCALE returns a two-dimensional uint8 image. Regenerate stored reference images from 0.31.4. (#2854, #2855, #2840, #2841)

📝 Notable changes

🔧 Fixed

Datasets

  • detections_to_createml_annotations and detections_to_pascal_voc raise ValueError for a class_id outside classes; a negative id was exported under the last class name and a too-large id raised IndexError. (#2859)
  • DetectionDataset.merge raised ValueError when some annotations had no class IDs; it now keeps them and remaps the labeled ones. (#2858)

Metrics

  • MeanAverageRecall counts objects of area exactly 32² or 96² in both neighbouring COCO size buckets, as MeanAveragePrecision does. (#2848)

Detections, VLM and slicing

  • Detections.from_ultralytics passed an empty crop to image resizing when restoring masks from thin letterboxed images; it now keeps at least one content pixel per axis. (#2857)
  • scale_boxes keeps representable corners when opposite-sign float coordinates overflow the intermediate box width, including float16 boxes from -40000 to 40000 scaled by 0.5. (#2853)
  • Qwen parsing skips malformed or non-finite boxes and keeps the valid detections from the same response. (#2851)
  • PaliGemma parsing keeps punctuation in class labels such as person (left) and cat/dog, so class filtering no longer drops them. (#2852)
  • Detections.from_vlm returns an integer class_id when a Gemini classes filter removes every detection and when a DeepSeek-VL2 response has none; it was a float64 array. (#2839)
  • InferenceSlicer(compact_masks=True) keeps the dense masks on callback-owned detections, so callbacks that reuse their output buffers no longer raise AttributeError after the first tile. (#2847)

NumPy fallback without OpenCV

  • Image reads honor IMREAD_GRAYSCALE for files and bytes, including sv.load_image_from_url(..., cv_imread_flags=0), and keep the high byte of 16-bit grayscale PNG and TIFF images. (#2841, #2840)
  • cvtColor(..., COLOR_BGR2GRAY) converts uint16 images with OpenCV's fixed-point weights. (#2855)
  • Drawing operations and copyMakeBorder saturate colors and round floating-point inputs for integer images; out-of-range border constants no longer raise OverflowError under NumPy 2.x. (#2854)
  • blur, approxPolyDP and intersectConvexConvex take OpenCV's parameter names, so keyword calls work, and intersectConvexConvex(handleNested=False) returns no intersection for strictly nested polygons. (#2856)
