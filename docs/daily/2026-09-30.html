v5.1.5 Stable2026-09-30T10:41:08Z

Big thanks to @ashmoonori-afk, whose #9209 teaches memory recall to find Korean, Japanese and Chinese notes and to pick the right note out of a big memory.

Hotfix: eval works again in the standalone omo binary. (#9248, #9250) The 5.1.3 and 5.1.4 binaries from GitHub Releases and get.omo.dev left out @babel/parser, which the eval tool loads, so JavaScript and Python eval were missing on every OS; npm and bun installs were fine. Each release now refuses a binary in which eval does not register and run.

Added

Memory recall finds Korean, Japanese and Chinese notes and picks the right note out of a large memory with nothing to configure, while an English phrase that matches a note word for word still comes first. (#9209)

The Recommended profile tries GPT-6.1 Sol (medium) before GPT-6 Sol on your ChatGPT subscription or the OpenAI API, and GitHub Copilot and OpenCode Zen keep GPT-6 Sol. (#9237)

In the standalone binary, omo setup now imports your settings, omo doctor prints the same sections as an npm install, and omo doctor --reap cleans up the binary's own stale engines. (#9252, #9253, #9265)

omo.dev has guide pages on mass ulw runs, agents, keywords, telemetry and desktop updates under /docs/. (#9261, #9264)

Fixed

OmO no longer slows your machine down with many sessions open, because memory recall reads the memory repository with one git batch per reload instead of one git process per note. (#9251, #9254)

The Windows release .exe runs from the folder you downloaded it to instead of failing at startup. (#7485, #9255)

The standalone binary downloads the Claude Code version it is pinned to on your first Claude subscription turn, checks its hash and caches it, so you no longer need claude installed yourself, and omo doctor shows it. (#9262, #9266, #9276, #9277)

One invalid value in omo.jsonc no longer switches off the whole file: only that key is ignored, omo doctor prints one warning naming it, and an unsafe key like __proto__ is dropped without losing its valid neighbors. Thanks to @mooire733. (#7676, #9249)

On Windows those config warnings name the file as ~/.omo/omo.jsonc. (#9244)

omo daemon reads its settings from ~/.omo/omo.jsonc like the rest of OmO, and a setting left in the old ~/.omo/agent/omo.json still applies with a warning in omo doctor. (#9192, #9199)

A foreground subagent waits at most 15 minutes before it moves to the background, even when a long prompt-cache window would allow an hour. (#9236)

v5.1.3 Stable2026-09-29T19:40:07Z

Changed

  • OmO Native moves from senpi 2026.9.29-3 to senpi 2026.9.29-4; the engine changes below come with it.

Breaking: an untrusted project's legacy .pi/ resources no longer load. (senpi#2375) Extensions, skills, prompt templates, themes and hooks under a project's .pi/ now follow project trust like the rest of the project config. A project whose only project resources are in .pi/ now asks whether you trust it instead of opening as trusted. Trusted projects load them as before.

Breaking: interactive sessions no longer join a shared engine host. (senpi#2328) Every interactive launch runs on its own local runtime. Extensions lose pi.sharedHostEnabled, and the experimental.sharedHost setting and the SENPI_ENABLE_SHARED_HOST / SENPI_DISABLE_SHARED_HOST variables are ignored if set. On first load experimental.sharedHost is removed from the global settings file.

Local sessions can pass messages and whole sessions to each other. (senpi#2328) An extension can open a terminal session to other local sessions with pi.session.registerControlEndpoint, and each message delivered that way is admitted once and waits while you are typing. A multi-session host hands a quiet session to your terminal with release_session, and with interrupt: true it stops the running work first and returns what it took out of the queue. Host status shows each endpoint's kind, whether it answers and who owns it, and a suspended terminal no longer holds the listing for 10 seconds.

Claude answers in your language. (senpi#2366) With a "reply in Korean" rule, or when you write in Korean, the routing line, the handoff block and todo labels come back in that language. The handoff labels (Ask, For you, Now, Next) stay as they are. Thanks to @floweredao for the report.

The engine installs smaller and faster. (senpi#2360, senpi#2362) senpi now declares its real dependencies instead of shipping its whole dependency tree inside the tarball, and it no longer ships sourcemaps.

Fixed

Memory recall works on a machine whose quick-category pin names only providers you are not logged into. (#9216) With categories.quick.models pinned to, say, OpenAI while only another provider is connected, Kibitzer started its recall judge on the pinned model, which failed at once with "No API key found", so recalled-memory nudges never arrived. Kibitzer now starts on the first connected model, your pins first and then the category's built-in chain, and when nothing is connected it shows the "Kibitzer unavailable" notice naming the providers to connect. The task tool still uses your pin as written.

Teams and process-mode subagents work again on installs made under umask 002. (#9208) With the Ubuntu default umask for private-group users, npm installed the task-host launch spec group-writable, the task host refused it, and every team_create failed with only "The task host is unavailable." OmO now makes that file private (0644) when it launches, never following a symlink and never touching a file another user owns. When the task host still refuses the spec, the task, the team_create error and omo doctor name the file and the fix (chmod 644 <path>). Reported and diagnosed by @devswha.

An npm-installed comment checker is found again, in the old and the new package layout. (#9180) The OpenCode edition's comment-checker hook looked for @code-yeongyu/comment-checker only in the bin/ folder its install script used to fill, so an npm install of 0.7.1 or later (binaries under vendor/) was never used and the hook fell back to downloading its own copy. The hook, omo doctor and the LazyCodex fallback now find the binary under vendor/ and in the per-platform packages the checker is moving to. Those packages cut its install from about 255 MiB to 51 MiB.

Agent mailbox state no longer lands in your repository. (#9201) OmO Native's thread tools kept their mailbox and receipts in <project>/.omo/thread-tools. They now live in the same per-project state folder as task state, outside the project. A project that already has the folder keeps using it.

A Claude Request not allowed error no longer strands a session on a fallback model. (senpi#2376) A transient 403 from a Claude subscription is retried on the same model before the session falls back. A fallback target that answers with a billing error no longer pins the session: that provider is skipped for its cooldown, and the next turn returns to your original model with a notice saying why.

A project you trusted loads its .agents/skills again. (senpi#2371) They appear under /skill: without launching with --approve. An untrusted project no longer picks up resources another session loaded from the same folder as trusted. Thanks to @sorenjuul for the report and the root-cause analysis.

Session files survive a failed write. (senpi#2328) Opening a session saved by an older version rewrites it through a complete copy, so a full disk or an I/O error keeps the original intact. A write refused for permissions or space no longer leaves the refused entry in the session, and a prompt whose messages could not be saved reports that error. A refused delivery, a half-written first save or the release of a never-saved session no longer leaves a session stuck or ends an engine host.

Every extension_ui_response gets a reply. (senpi#2372) A host or a terminal endpoint that settles one answers with the frame's own id, so a client can tell a delivered answer from a lost one.

The startup banner is no longer red. (#8442) Under Bun, omo printed its version banner, the omo setup credentials hint and the legacy-settings notice in the error color, so a healthy start looked like a failure. They now print without color; the text and the stream are unchanged. (#8870 by @cynkai)

omo update no longer reports success while leaving the old version installed. (#9198) It now looks up the version published on your channel and installs exactly that, for example bun add -g omo-ai@5.1.2. If you are already on it, nothing is installed. If the package manager finishes but OmO is still on the old version, omo update says omo is still <old>; <new> is published, prints the command to retry, and exits with an error. omo update --dry-run shows the exact command. When the npm registry can't be reached, it installs the unpinned omo-ai as before and tells you it could not confirm the version.

omo update --help shows help instead of updating. (#9207, reported by @devswha) omo update --help and omo update -h used to run the install, and so did a mistyped flag. They now print what omo update does and its flags. A flag it doesn't know, such as --forse, stops with omo update: unknown option --forse and installs nothing. The compiled omo binary answers the same way.

Four security vulnerabilities have been identified, and fixed, in this release. Users are advised to update gh to version v2.102.0 as soon as possible.

gh release download, gh run download, gh repo read-file --output, and gh attestation download could write remote content to an unintended local file when the destination contained symbolic links.

See https://github.com/cli/cli/security/advisories/GHSA-39wj-f2f4-978v for more information.

gh attestation verify compared the --source-ref value case-insensitively, so an attestation built from a branch whose name differs only in case could satisfy a policy that named a different branch.

See https://github.com/cli/cli/security/advisories/GHSA-4mq3-hpgx-9cx8 for more information.

Interactive gh skill search passed repository paths from search results to gh skill install without an option separator, so a search result could inject installer options and change where skill files were written.

See https://github.com/cli/cli/security/advisories/GHSA-qcwj-mr2r-2cx7 for more information.

gh attestation verify matched the --signer-workflow value against only the start of the signing certificate's identity, so an attestation signed by a different workflow in the pinned repository could pass verification when its path began with the pinned value.

See https://github.com/cli/cli/security/advisories/GHSA-wjmr-j3rp-mh2g for more information.

The short version

Codex: Codex workers start again on current Codex (0.158). Orca had been waiting for a welcome-screen label that Codex 0.158 removed, so every Codex worker timed out; Orca now recognizes Codex's empty input box instead. Starting a Codex worker with a model or reasoning effort no longer hangs either.

Codex tabs run on their own: On Codex 0.157 and newer, every Codex tab in Orca shared one background server started by the first tab, so status and results were credited to the wrong tab and closing the first tab dropped all the others. Each Codex tab in an Orca terminal now runs its own server, so closing one no longer drops the others. New terminals opened after updating get this; terminals already open keep the old behavior until reopened. To keep the shared server, add export ORCA_CODEX_ISOLATE=0 to your shell startup file. The trade-off of the default: Codex "Run in background", codex agents, and opening a session from the Codex desktop app or an IDE won't see sessions started in Orca, and many open tabs use more memory.

Status bar & workspace UI: The status bar fits small screens: extra agents fold into a "+N" badge before status labels shrink to icons. Compact agent rows show unread emphasis, and activity threads from floating terminal agents open the right pane.

Remote & SSH: SSH hosts that ask for a verification code or other multi-factor prompt are supported, remote file access follows repository ownership, and interrupted remote installs recover without deleting files still in use.

Editor & browser: Solidity, Typst, and Twig files are highlighted, Markdown source survives rich-text edits, and browser tools fold into a menu on narrow screens.

Reliability: Orchestration workers whose terminal can no longer be found are stopped properly instead of piling up, and many background tasks clean up after themselves when a window reloads or a request is cancelled.

v1.7.2v1.7.2 - Measured PDFs, CLIs that stop trusting the digits, tools that survive non-ASCII Stable2026-09-29T18:32:55Z

A patch release with one theme: the checks the workflow documented now actually run, and the tools stop breaking on anything that is not ASCII. Compiled PDFs get measured instead of eyeballed, the portal CLIs stop trusting the digits in a URL, and every Python tool survives a Cyrillic posting or a Turkish robots.txt on Windows. Thirty-two entries, twenty-four of them fixes, most reported and fixed by contributors within days of each other.

Highlights

/apply measures the PDF instead of looking at it (#378, #476, #458, #498, #465)

tools/verify_layout.py measures what Step 5b previously only eyeballed: per-page text extent, bottom whitespace, the largest internal gap, footer collisions, and an entry header stranded at a page break. It exists for a failure every other check missed: a moderncv \cventry is unbreakable, so an entry that does not fit jumps to the next page and leaves a hole while the document still compiles, still has the right page count, and still passes verify_pdf.py. Step 5b now also runs the page-count check it had been claiming Step 5d ran (nothing in the workflow passed --pages at all). verify_pdf.py --contains sees through LaTeX's typographic substitutions, so --contains "Master's degree" and --contains "2016-2024" no longer report a keyword missing from a document that plainly contains it, and the new --ascii-dates flag reads the raw text layer for the one thing the fold must not hide: a year joined to an en-dash, which a real Workday import dropped together with the date. Poppler stays optional; a missing or xpdf pdftotext degrades to a skipped: exit 2 that now names both causes.

Portal CLIs stop trusting the digits (#448, #500, #435, #460, #504, #505)

jobindex-search detail fetched any URL verbatim and, when the path did not match, returned a well-formed fake posting built from whatever page came back. linkedin-search detail took the first six-plus-digit segment from any URL, so a Greenhouse or Lever apply link fetched whichever LinkedIn posting carried that number, with exit 0. Both now parse the host for real and exit 1 with the BAD_ID contract before any request, matching the rest of the CLIs. jobnet-search detail no longer reports an externally hosted ad as not found, jobdanmark-search detail backs off on 429/5xx like every other portal, and freehire-search decodes HTML entities in titles and keeps the salary period, so a yearly figure no longer reads as monthly.

Non-ASCII stops crashing the tools, especially on Windows (#490, #486, #485, #487, #506, #480, #503)

A piped stdout on Windows defaults to the ANSI code page, and that is how Claude Code runs every tool. A single Cyrillic, CJK, Devanagari, Polish or Turkish posting ended /rank with UnicodeEncodeError before any output reached the workflow; every Python tool now writes UTF-8 at entry, and the Linux CI reproduces the Windows failure through PYTHONIOENCODING. /rank's tracker matching keeps Unicode company and role names instead of collapsing them to nothing, handles a BOM on a reordered CSV header, and rejects invalid score dimensions before saving. Distinct non-Latin company names no longer share the unknown-company job key. robots_check.py decodes curl output as UTF-8, so a robots.txt with a CJK rule no longer reads as UNCONFIRMED on a Windows locale, and a non-ASCII disallow rule that silently never matched now does. Two docstrings that quoted \h and \s unescaped printed a SyntaxWarning on every run; both are fixed and a compile check over tools/*.py and tests/*.py keeps the next one out.

State on disk stays honest (#441, #425, #440, #455, #444)

seen_jobs.json keys are now a pure function of the posting, owned by tools/job_key.py instead of described in prose, so two runs can no longer store one job twice by truncating a title at different points; --audit reports legacy entries and never rewrites them. /gmail-sync and /outcome keep commas, quotes and line breaks out of the tracker's notes column, which used to shift three columns left on a subject as ordinary as Re: Your application, Data Scientist. /outcome and /interview no longer confuse two roles at the same company when archiving. And the 09-web-research.md curl snippets fail loudly when $SCRATCHPAD is unset instead of writing into the checkout.

New in the workflow (#467, #468, #437, #439, #474)

/apply Step 1 verifies the posting URL's host against installed portals and the six standard ATS apexes, flagging look-alikes and unknown hosts before any drafting tokens are spent. /setup ingests project writeups from documents/projects/, and /expand mines public GitHub repositories, both into the ## Independent Projects section of the profile. /outcome stale [N] batch-resolves applications quiet for 60+ days with explicit confirmation. /add-template keeps a registered template's intermediates in build/.

  1.   2. cv/main_example.tex gains one guarded preamble line, \ifpdftex\usepackage[T1]{fontenc}\fi, a no-op under lualatex. A clean 3-way merge unless you edited the preamble; tailored CVs compiled with lualatex need nothing.
  3. .claude/settings.json gains four path-scoped lines (tools/job_key.py and tools/verify_layout.py, python and python3 each) and tools/security_guards.py requires them; .gitignore gains build/ and documents/projects/**. Forks with their own allowlist should take both hunks.
