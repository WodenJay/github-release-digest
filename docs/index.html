HyperFrames v0.8.150

Released on 2026-10-12.

Video frame injection now releases replaced image resources, keeping render memory from growing with every frame. Composition-wide audio effects and scene export fixes also ship in this release.

Compatibility notes

  • A top-level composition root's data-fx-chain now processes the whole audio mix. Remove a previously unused root chain if you want unchanged audio. #5420
  • For engine API users, injectVideoFramesBatch assigns temporary image URLs that expire after decoding. Use the original frame source when serializing or reloading the DOM. #5494

Features

  • Apply one audio effects chain across the whole composition, after clip and group effects. Set data-fx-chain on the top-level root. #5420

Fixes

  • Exported video and audio now respect split scenes' in-points and inline scenes' start times, matching their placement in preview. #5454
  • A scene previewed or rendered alone uses its own master audio chain. #5474
  • Pitch-shifted exports keep the end of the clip and its effect tail. Bitcrush preview no longer starts with a silent hold after seeking. #5478
  • Studio history diagnostics include the server status and reason when an edit cannot be recorded as an undo step. #5489

Performance

  • Replaced video frames no longer accumulate cached image resources during capture. Engine-owned capture pages also retain less response data for DevTools inspection. #5494
  • Large audio effects mixes render in windows instead of loading the full mix into the browser. Parameter automation above 2 GiB remains unsupported. #5474

Catalog

  • The product-promo example no longer fails lint on conflicting CSS and GSAP transforms, allowing its browser audits to run. #5481

longbridge/gpui-kit ↗ 1 release · 1 stable
v0.7.3 Stable2026-10-12T07:27:58Z

GPUI Kit v0.7.3 replaces v0.7.2, which is yanked: it contains every v0.7.2 change and moves GPUI to the gpui-pre 0.3.9 snapshot. Upgrade from v0.7.1 or v0.7.2 directly to v0.7.3.

This release adds a readonly Diff viewer with a Git history example, an optional GPUI Fast backend, and configurable dialog entrances. It refreshes TextView typography and improves text selection, Editor completions, tables, menus, tooltips and accessibility, and stops several per-frame state writes that made long scrolling views rebuild.

New components and runtime

  • Diff: display application-supplied unified or Git patches with the virtualized, readonly Diff view. DiffFile::parse prepares each file and one DiffState shows them all, with Unified or Split layout (DiffMode), syntax highlighting, folding, change navigation, inline word or character emphasis, soft wrapping, annotations, and two-way or diff3 conflict display. Applications own patch loading, review comments and saving. (#3378)
  • Git history example: examples/tig is a desktop Git history browser built on Diff, with a resizable commit and file sidebar, Split layout and a settings menu; the Diff review APIs it needed are complete. (#3388)
  • GPUI snapshot: exact snapshot dependencies are updated to =0.3.9 (zed@93d7456), and the optional GPUI Fast backend requires gpui-fast 0.1.7 on the same snapshot. (#3459)
  • GPUI Fast backend: enable the optional gpui-fast feature (gpui-kit = { version = "0.7", features = ["gpui-fast"] }) to run on GPUI Fast instead of the default gpui-pre backend. Imports and macros are unchanged, and Windows applications embed a single manifest. (#3375, #3380)
  • Fewer rebuilds: selectable text, the text selection layer, Root, inputs, TextViewState and resizable panels no longer write state on frames where nothing changed, so retained views under GPUI Fast stay on their scroll layer. (#3407, #3418)

Editor and text input

  • On-demand completions: dispatch the Editor-only ShowCompletions action or call show_completions to request suggestions from a command, menu or application shortcut; no default shortcut is bound. (#3411)
  • Programmatic multi-cursor: InputState::add_selection adds a selection while keeping the existing ones, enabling features such as select all occurrences. (#3403)
  • Context menus: an input keeps its selection and focus ring while its context menu is open, and submenus inherit the parent menu's action_context, so actions such as Select All reach the source Textarea. Custom on_context_menu builders now run after the input is released and can read its cursor and text. (#3382, #3433)
  • Fixed completion and code-action popups lagging one frame behind the caret, and auto-grow Textareas collapsing to min_rows after set_auto_grow changes the limits. (#3412, #3430)

Markdown and text rendering

  • Typography: TextView headings build hierarchy with weight, sizes and spacing scale with the inherited font size, and lists, code, links and tables are more restrained. See Behavior changes. (#3371)
  • Selection: mouse selections include block MarkdownPlugin content as whole blocks, completed selections survive style, zoom and width changes, and the selection paints under the glyphs so opaque selection colors keep text readable. (#3373, #3390, #3421, #3439)
  • Tables: narrow columns size from measured text width and stay on one line, and rounded table frames keep clean corners at any horizontal scroll offset. RoundedFrameCover is available for application frames with their own rounded scroll viewports. (#3399, #3309, #3400)
  • Fixed inline <mark> highlights in Markdown, including color and background-color attributes. (#3425)

Components

  • Dialog: choose an entrance with entrance(DialogEntrance::Fade), FadeSlide, None or the default SlideDown on Dialog and AlertDialog; AlertDialog::margin_top moves an alert off the default top offset. (#3405, #3404)
  • Tooltip: install TooltipDefaults to set the application-wide show delay and grace period, or override one trigger with tooltip_show_delay. (#3376)
  • DataTable: header_row_height sets header rows apart from body rows; the sort icon is a labelled button; visible_rows_changed reports one-row and empty tables; a right-clicked cell's outline clears on the next click, exposed through TableState::right_clicked_cell. (#3420, #3396, #3397, #3413)
  • ContextMenu: a long press opens the menu on touch devices, and the menu takes focus before its first frame, avoiding a debug-build abort with accessibility active. (#3393, #3422)
  • TabBar: clicking a clipped tab scrolls it into view with the next tab peeking. (#3419)
  • Dock: closing the focused tab hands focus to the tab that replaces it. (#3409)
  • DropdownButton: menu_accessibility_label names the caret-only menu trigger, with a localized "More options" default. (#3410)
  • Settings: focus rings stay inside the list viewport. (#3394)
  • UI tests: Progress, ProgressCircle and TitleBar can be found with TestWindowExt::find. (#3383)

Documentation

  • Focus and dialogs: the guides explain recovering focus when the focused element stops rendering, and the open_dialog builder and footer contracts. (#3386, #3406)

Behavior changes

TextView renders with new default typography. Heading sizes follow the inherited font size, the paragraph gap is 0.75rem (was 1rem), and list, inline code, link and table cell styling change. The paragraph gap, headings and code blocks can be restored through the existing style hooks. (#3371)

 TextViewStyle::default()
+    .paragraph_gap(rems(1.))

Table column widths in the default wrap layout change for most Markdown tables. A drag that starts and ends inside the same block plugin no longer selects it. (#3399, #3390)

While a context menu is open, focus that the application moves elsewhere is no longer pulled back to the menu. (#3422)

TableDelegate::visible_rows_changed now fires with 0..1 for a one-row table and 0..0 when the rows drop to none, and its end never passes rows_count. (#3397)

TooltipRequest::placement is deprecated in favor of with_placement. (#3376)

- TooltipRequest::new(bounds, build).placement(Placement::Right)
+ TooltipRequest::new(bounds, build).with_placement(Placement::Right)

What this patch ships for source installs (hermes update and the desktop app's updater on a git checkout):

  • Updates now follow tagged releases. A source install of the official repository updates to the latest published vX.Y.Z release instead of every commit on main. An install already newer than the latest release stays where it is and waits for the next one; nothing is moved back. To keep following every commit: hermes update --set-channel main. Forks and mirrors keep following main. Store, MSIX and bundled desktop installs are unchanged.
  • Choose the channel in the desktop app. Settings ▸ About ▸ Updates has an Update channel switch (Stable releases / Every commit) for source installs, and the update dialog now shows which channel you are on.
  • Reasoning survives resume. Signed thinking replays after hermes chat --resume and on the next gateway turn, and Bedrock Converse reasoning models no longer get rejected on resumed sessions.
  • Updates no longer fail behind some firewalls. Installs on main no longer fetch a release record that regional firewalls could answer with 403. The stable check uses your GitHub token when one is set (GITHUB_TOKEN or gh auth login) and reports a GitHub rate limit as a rate limit.

studio-v2.36.0Reasonix Studio v2.36.0 Stable2026-10-11T19:22:00Z

本版加入提问等待超时、可选提示音、可选的折叠中间过程、每回合运行时长、改动文件条、工作区额外文件夹设置和编辑连接时更改协议，回执卡改为默认隐藏，并修复 1M 窗口每轮 400、存储迁移卡在校验、滚轮抖动、模型切换被后台任务挡住、Linux 与 Windows 更新等问题。

新增

  • 新增可选的提问等待超时（默认关闭）：设置的会话页、[agent] ask_timeout_seconds 或终端 /ask-timeout 开启后，无人回答的提问超时即跳过，并告诉模型这是超时而非你的回答 (#12661)
  • 每个回合结束后显示它运行了多久，重新载入历史后仍能看到；失败或被取消的回合不显示，旧会话也不补造 (#12656)
  • 输入框上方新增改动文件条，显示「N 个文件已更改 +x -y」，点击打开工作台文件列表；默认开启，可在会话设置里关闭，非 git 工作区不显示 (#12668)
  • 外观的行宽新增「整宽，输入框也铺满」，默认不变，需要时自己选；手机宽度不受影响 (#12703)
  • 设置的「工具与权限」里新增「此项目的额外文件夹」：可添加、移除让 agent 额外可写的文件夹，只对本项目生效，拒绝时给出带代码的原因，默认没有；「完全放行」只决定是否询问，不会扩大可写范围 (#12640, #12715)
  • 新增可选的提示音（默认关闭）：设置的通知里打开后，回合结束、等待批准、模型提问和反馈回复时放一声短提示，不依赖系统通知，窗口在后台也会响 (#12702)
  • 新增可选的「折叠中间过程」（默认关闭，[ui] fold_turn_work）：已结束的一轮只留最后一句，中间的工具调用、思考和中间文字收成一行，点开展开，运行中的一轮始终展开 (#12714)
  • 设置的版本页新增「日志与异常退出记录」：显示日志目录和异常退出留下的文件，不上传任何东西 (#12719)
  • 编辑连接时可以更改协议，不必删掉重建；决策来源不显示该选项，已固定请求地址的连接会被拒绝并说明原因 (#12618)
  • 界面字体与代码字体的建议列表大幅扩充，在 Windows 上不再几乎没有可选项 (#12708)
  • 斜杠菜单里的 MCP 提示词会列出它声明的参数，并标明必填或可选，Studio 和终端界面都有 (#12700)
  • 窗口关闭后重新打开，会回到上次的大小、位置和最大化状态 (#12624)
  • 不带任务编号调用 bash_output 时，列出正在运行的后台任务及其开始时间，模型不必自己记任务编号 (#12627)

变更

  • 回执卡默认隐藏：有未验证的改动时只留一行，点击展开；在设置里或 [ui] show_receipt 可恢复显示，终端界面读同一个设置 (#12721)
  • 打开工作台时先出入口页（文件、改动、浏览器），不再替你打开浏览器；标题栏的浏览器按钮仍直达浏览器 (#12648)
  • 侧栏开关只有一个且位置不变，会话项点击有动作，同一模型连续回复只在首条显示头像和名字 (#12647)
  • 运行分析的信号栏说明它是什么、为什么标记不能拖；窄窗口加高缩放下标题栏折成一个按钮，不再互相压住 (#12646, #12616)
  • 宿主拒绝过的调用会在下一轮告诉模型（只回传确定不可重试的几类），被拒说明也不再写「本会话剩余时间」 (#12697)

  • 设置、用量等机器级页面在远程窗格里也绑定本机运行时，被替换的控制器的货币保存会被拒绝 (#12674 by @XTLine)

重新梳理的供应商添加流程

这一版把添加和编辑供应商的表单从头到尾理了一遍，主要是 Claude Code、Codex 和聚合三种布局。以前模型列表收在高级选项里，排在它所决定的默认模型后面；获取到的模型只能在列表下方逐个添加，加完还要逐个核对自动填好的参数；几乎每个字段下面都有一段灰字，有些提示和你实际所处的模式对不上。现在按填写顺序走一遍：

1. 地址、Key 和上游格式。 先选预设或填地址和 Key。选上游格式时，提示按应用当前的模式显示：应用处在直连模式时，如果选的格式需要转换，格式下面会提示这张卡正在直连使用、改成这种格式保存后请求会失败，或者这种格式要先切到路由或聚合才能用。Claude Code 的上游格式选 OpenAI Chat 或 Responses 时，不再显示用不上的认证字段。

  3. 勾选想要的模型，点「应用」。新模型追加到列表末尾，参数按弹窗里显示的值直接填好，不再弹「已补全……的上下文等参数，请核对」的提示。

同一个弹窗也负责删除：勾选表示「在列表里」，已配置的模型默认勾选，取消勾选后点「应用」就会从列表移除，点「取消」什么都不改。留下的模型保持原来的顺序和设置。已配置但供应商这次没返回的模型，单独列在「不在供应商列表中」一组，也能一并清理。弹窗支持搜索、全选 / 全不选、只看已选，并显示已选数量；获取过一次后按钮变成「选择模型」，再点不会重新获取，需要时在弹窗里点「重新获取」。

3. 默认模型：列表第一行。 Codex 有模型列表时，第一行就是默认模型，不再单独有一个默认模型输入框；改名或删掉第一行，默认模型跟着变。列表原本为空时，添加模型会自动把当前的默认模型放在第一行，默认模型不会因为加了列表而变掉。没有配置模型列表的卡仍然保留默认模型输入框：这类卡用的是 Codex 自带的 /model 菜单，加上列表后菜单里只会剩下列表里的模型。聚合模型列表也去掉了每行的 ★ 和「设为默认模型」，规则同样是第一行即默认。

4. 子代理（Codex，新增）。 Codex 表单新增「子代理模型」和「子代理推理强度」，对应 config.toml 里 [agents] 下的 default_subagent_model 和 default_subagent_reasoning_effort。留空就删掉对应的键，子代理沿用主代理的设置；切换供应商时这两项跟着换，[agents] 下的其他设置不动。填的模型不在模型列表里时，表单会提示并可以一键加入：不在列表里的模型，Codex 拿不到它的上下文窗口，经路由转成 Chat / Anthropic 协议时还会被换成默认模型。聚合模式下不写这两项，子代理跟随主模型，以免主代理换到另一家的模型后，子代理又被送回默认供应商。

5. 高级选项。 「完整 URL」开关只对端点路径不标准的网关有用，挪进了高级选项；已经打开它的卡，编辑时高级选项会自动展开。User-Agent 和请求覆盖合成一块，统一注明只在路由和聚合模式下生效。

贯穿整个表单：说明收进「?」。 字段是什么、什么时候用，放在字段名后面的「?」里；页面上只留需要你注意的后果，比如改了模型列表要重启 Codex、最大输出超过实际上限会报 400。托管账号的卡（Codex、xAI 登录和 Copilot）上，后端本来就不读的字段不再显示；旧版残留字段的提示缩成一句话；Claude Desktop 的模型模式说明改成一句话：供应商提供原生 Claude 模型时用直连，DeepSeek、Kimi 等第三方模型用模型映射。

新增

「设置 → 本地路由」新增「连接地址」。 CC Switch 写进客户端配置的代理地址（包括 Claude Desktop 的网关地址）以前总是按监听地址推导，监听 0.0.0.0 时写的是 127.0.0.1。WSL2（NAT 模式）里的 Claude Desktop 会话访问不到 Windows 的本机回环，所以一直连不上，把监听地址改成 0.0.0.0 也没用。现在把监听地址设为 0.0.0.0，再在「连接地址」里填 WSL 能访问到的 Windows 地址，写给客户端的代理地址就会改用它。保存后会直接改写正在走路由的客户端，不用重启路由服务。这个设置只保存在本机，不会随云同步带到其他设备。

新增预设： SoruxGPT、IKunCode、RunToken、BotCF、YYLX、TokenFlux、OpenModel。

修复

  • Codex 新建线程或跑自动化时，DeepSeek 等上游报 400，整个线程用不了。 Codex 桌面版新建线程时会往历史里插入一条没有对应工具调用的工具结果（create_thread 回执）。经路由把 Responses 转成 Chat 协议时，这类结果以前被当成 role=tool 消息发出去，DeepSeek、OpenCode Zen 这类严格的 Chat 上游会拒绝这个线程里的每一次请求。现在这类找不到对应调用的工具结果会改成一条带标记的用户消息，里面的图片照常作为图片发送；有对应调用的工具结果和以前完全一样。
  • Codex 用 xAI 原生 Responses 时报 422，线程无法恢复。 Codex 桌面版插入的回执（新建线程、自动化更新、心跳、跨线程消息）没有 call_id，xAI 会以「缺少 call_id」拒绝整个请求，而回执一直留在历史里，所以这个线程之后都发不出去。现在只在发往 xAI 时，把这类回执改写成带同样标记的用户消息，保留文字和图片；有 call_id 的条目和其他上游都不受影响。
  • Claude Code 的上游格式选 OpenAI Chat 或 Responses 时，路由发出的是 x-api-key。 以前请求头只看 Key 的变量名，用 ANTHROPIC_API_KEY 的卡会发 x-api-key，OpenAI 格式的上游不认。现在 OpenAI 格式一律用 Authorization: Bearer，Anthropic 格式仍按变量名决定。
  • Claude Code 聚合模式只用默认供应商的兼容开关。 选到其他供应商的模型时，可能发出那家不支持的功能而报错。现在按开关的性质合并所有成员的设置：关闭实验性 beta、Artifact、自动模式服务器这类，只要有一家关就关；工具搜索、始终启用 effort、细粒度工具流式这类，所有成员都开才开。额外请求体、思考和窗口相关的开关仍然跟随默认供应商。
  • 启动时界面语言不对，打开设置页后才变回来。 首屏语言读的是浏览器缓存，缓存为空或过期时（比如清过 WebView 数据、把 ~/.cc-switch 复制到新电脑）会先显示系统语言。现在启动时会读取保存的语言设置并立即应用。
  • macOS 上连不上局域网里的 API 地址。 CC Switch 现在会向 macOS 申请「本地网络」权限。第一次连接局域网地址时系统会弹出授权，这次请求可能仍然失败，点「允许」后重试即可。如果以前点过拒绝，需要到「系统设置 → 隐私与安全性 → 本地网络」里打开 CC Switch。
  • 打开供应商编辑面板时页面闪一下。 编辑面板以前先打开一个加载页再换成内容；现在等内容准备好再打开，保留和新增面板一样的淡入效果。

其他： Flatpak 构建文档修正了 --bundles 参数的写法，并说明没有签名私钥时怎么跳过更新包。
